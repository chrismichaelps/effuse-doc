# なぜ Effuse なのか

Effuse は、コンポーネントの境界ではコードを小さく保ちながら、アプリケーションの
機能を明示的・型安全・テスト可能なままにしたいチームのために存在します。

React は広いエコシステムを、Vue は親しみやすいコンポーネントの使い心地を、Solid
は細粒度のリアクティビティを、Next はサーバーサイドのアプリケーション基盤を提供
します。Effuse は、これらの優れた考え方を 1 つの契約のもとにまとめることで存在
価値を示すべきです。すなわち、レイヤーがアプリケーションの機能を定義し、
コンポーネントはローカルな名前でその機能を利用し、サーバーのルートとアクションは
それらを所有するサービスの隣に置かれます。

## 課題

多くのフレームワークでは、アプリケーションが切り離された多数の面に分散します。

| 必要なもの               | よくある摩擦                                           |
| ------------------------ | ------------------------------------------------------ |
| 共有サービス             | グローバルモジュール、コンテキストツリー、型のない注入 |
| サーバー API             | サービス層から乖離していく独立したルートファイル       |
| コンポーネントのロジック | hook や import の氾濫と暗黙的な実行時依存              |
| リアクティビティ         | 粗い再レンダリング、境界が不明瞭なコンパイラの魔法     |
| テスト                   | ビジネス機能と UI コードが別々の継ぎ目でテストされる   |

Effuse は、コンポーネントのコードを重くすることなく、これらの境界を明示的に
すべきです。

## Effuse の契約

1. レイヤーが機能を所有する。
2. コンポーネントと hook は `layers` を通じてローカルに機能を取り込む。
3. サービスはレイヤー定義から型付けされる。
4. サーバーのルートとアクションは、データを所有するレイヤーに宣言する。
5. 細粒度のシグナルが、依存する UI だけを更新する。

```tsx
const AuthLayer = defineLayer({
  name: 'platformAuth',
  services: {
    auth: () => ({
      currentUser: () => ({ id: 'u1', name: 'Chris' }),
    }),
  },
  server: {
    api: {
      '/api/me': ({ services }) => services.auth.currentUser(),
    },
    actions: {
      refreshSession: ({ services }) => services.auth.currentUser(),
    },
  },
});

const ProfileButton = define({
  layers: { auth: AuthLayer } as const,
  script({ layers: { auth } }) {
    const user = auth.services.auth.currentUser();
    return { user };
  },
  template: ({ user }) => <button>{user.name}</button>,
});
```

レイヤー名はグローバルに一意なまま（`platformAuth`）にしつつ、コンポーネントは
好きなローカル名（`auth`）を使えます。これによりアプリケーションのグラフは安定し、
コンポーネントの記述は読みやすく保たれます。

## 採用する価値

- 機能優先のアーキテクチャ: 認証、データ、アナリティクス、フィーチャーフラグ、
  API ルートが、隠れた import ではなく明示的なアプリモジュールになります。
- 優れたコンポーネント DX: `define({ script, template })` がロジックと UI を
  近くに保ち、`layers: { auth: AuthLayer }` が文字列による探索と props の
  バケツリレーを不要にします。
- 型付きのサービスアクセス: `auth.services.auth` は `defineLayer` から推論され、
  コンポーネントがサービスの型を手書きで再宣言する必要はありません。
- サーバーサイドの機能: レイヤーが所有する `server.api` と `server.actions` に
  より、ルートを実装元の機能から切り離すことなく、Next のようなリクエスト面を
  得られます。
- 細粒度の更新: シグナルにより、既定でサブツリー全体を再レンダリングするのでは
  なく、状態変更が正確に反映されます。
- 本番でのテスト容易性: レイヤーのサービス、コンポーネントの script、サーバーの
  ルートを、同じ宣言済みレイヤーグラフを通じて個別にも一括にもテストできます。

## 目指さないこと

- Effuse は、あらゆるフレームワークの機能を量で模倣しません。
- Effuse は、アプリケーションの依存関係をアンビエントなグローバル変数の背後に
  隠しません。
- Effuse は、ローカルなエイリアスの方が明快な場面で、コンポーネントの作成者に
  レイヤー内部のグローバル名を知ることを要求しません。
- Effuse は、サーバーのルートをアプリケーションの機能とは別のシステムにしません。

目標は、より小さな表面積から、より強力なアプリケーションモデルを組み立てることです。
